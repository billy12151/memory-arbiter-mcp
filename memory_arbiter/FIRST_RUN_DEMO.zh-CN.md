# 首次使用功能验证规程（宿主 Agent 执行）

> 本文档是给宿主 Agent（ZCode / 其他 MCP 客户端里的 agent）执行的操作规程。
> 当用户首次接入 mema（memory-arbiter）时，按本规程演示能力并建立信任。
> **全程使用标准话术，不得自由发挥**（话术由 mema 维护方审定）。
> 状态：v4.1。v3 已 owner 终审冻结（2026-09-16；含隔离库真机彩排校准：相似应响
> 2 次成立、冲突 notice 暖库同步可达 0.7s、清理 8/8 闭环、open notices
> 零残留）；2026-09-17 owner 重开**话术层**修订：v4 全面白话化（§0 展示纪律 +
> 各节话术重写 + §5 文字图）；v4.1（同日）§2 演示语料的 subject 钉死为
> 逐字表格（近似对/冲突对同名标题，相似度 1.0）。实操步骤与接口钉子不动。
> 话术改动须走维护方审定，不得就地改。

## 0. 前提与边界

- **展示纪律（owner 2026-09-17，硬要求）**：话术受众是**没有研发背景的新用户**。
  ①全白话，不出现英文术语——工具名、参数名、标签名、状态码只存在于本规程
  「实操」里供 Agent 执行，一律不念给用户（产品专名 mema/迷码、语料里的
  GitHub/MySQL 等专有名词除外）；②**不把工具的原始返回贴给用户**——由
  Agent 翻译成人话；涉及两条记忆的提示（重复/矛盾），把**两句原文并排列出**
  再加一句白话解释，不贴 JSON/字段名；③必要处用简单文字图（见 §5 图式，
  产品名首次出现写「迷码（mema）」，之后只用「迷码」）；④数字照实报，
  哪项没触发就照实说没触发，不圆场。
- **全局最多提示一次（owner 2026-09-16 原则）**：本演示对同一用户只提示一次——
  已完成或用户已拒绝，**无论后续新接入多少个 Agent 都不得再提示**。提示前必须
  先查全局标记（§1 第一步）；拒绝或完成后必须写标记（§1/§7）。标记本身是 mema
  库里的普通记忆（`mema-first-run-demo-status` 标签），用户显式 retire 该标记
  才视为允许重新提示。
- 演示会往用户**真实记忆库**写入一组测试记忆，演示结束全部 governed retire（不物理删除）。
- **第一步必须征得用户明确同意，禁止未经同意写入。**
- 语义冲突模型（Qwen）不可用时，冲突演示标「未测试」，不得伪报通过或失败；
  相似提示不依赖 Qwen（embedder 缺失时走降级扫描，话术按「降级模式」如实标注）。
- **语言边界（2026-09-16 隔离库实测；同日随确定性直判通道更新）**：本规程语料
  与查询按中文设计。英文内容下召回、相似提示、按 ID 读均可用；英文冲突提醒
  分层——数值对立可出（0.16.6 确定性直判通道，不依赖 Qwen），语义对立的冲突
  notice 不出（规则层双语等价放行，Qwen 判定层处理英文证据未确认对立）；
  **跨语言查询为盲区**（中文查询查英文记忆返回 0，反之亦然）。演示时语料与
  查询语言保持一致；英文用户跑本规程时语义冲突演示应标「未测试」，不得伪报。

## 1. 同意门（标准话术）

**第一步——全局标记查询（硬前提，跳过即违规）**：

```
memory(action="find", data={"query": "", "tags_filter": ["mema-first-run-demo-status"]})
```

命中任何一条 active 记忆（无论 declined 还是 completed）→ **整个演示跳过，对用户
只字不提**（用户已拒绝或已看过，再提就是骚扰）。未命中才走下面的同意话术。

> 「我可以花一分钟，给你演示一下迷码（mema，你刚装好的 AI 记忆管家）是
> 干什么用的：我先往里写 8 条假的测试内容（比如『生产部署用两个机房』
> 这种），然后当着你的面演四件事——它记得住、查得到、内容写重了会提醒、
> 前后说法打架了也会提醒。演完我马上把这 8 条测试内容清掉，一条不留，
> 也不会碰你已有的任何记忆。要做吗？」

用户同意后继续；**拒绝则写全局标记后跳过整个演示**（这句话不说出口，静默记录）：

```
memory(action="remember", data={"content": "用户拒绝了首次功能演示（<日期>，agent=<宿主名>）。",
  "subject": "mema 首次演示状态：已拒绝", "tags": ["mema-first-run-demo-status"]})
```

写标记失败不得重试提示（宁可漏演示不再骚扰）：标记写入失败时同样跳过演示，
并在自己的本地记忆里记一条「本机用户已拒绝演示」，尽最大努力避免再次提示。

## 2. 写入演示数据

统一规范：每条记忆带必填的 `subject`（≤30 字）、标签 `mema-demo`、元数据
`purpose: mema_feature_demo`、`run_id: demo-<日期>-<4位随机>`（同一轮演示共用
同一 run_id）。`subject` 缺失会被 remember 直接拒绝；workspace 不用传，默认
落在 default 桶（概念见 §3①）。

**标题与正文逐字照抄下表，禁止改写、缩短或"顺手优化"**（owner 2026-09-17
拍板钉死）。原因：相似提醒的触发条件之一是两条标题相似度 ≥ 0.8
（`WRITE_SIMILAR_SUBJECT_RATIO`），§4 汇报里写死的「应该 2 次」完全建立在本表
标题上——标题一改相似度就会掉，演示静默少响一次（实测：整句口径 0.8163 勉强
过门、剥掉前缀 0.7692 被挡，余量薄到换一个模型起标题就翻车）。因此近似对与
冲突对**刻意用同名标题**（相似度 1.0，稳过门槛），这不是疏漏。

| # | 角色 | 标题 subject（照抄） | 正文 content（照抄） |
|---|---|---|---|
| 1 | 普通事实 | 金营平台生产部署架构 | 演示记忆：金营平台的生产部署采用双可用区架构 |
| 2 | 普通事实 | 用户语言与文档偏好 | 演示记忆：用户偏好中文交流，文档以中文为主 |
| 3 | 普通事实 | 项目例会时间 | 演示记忆：本周项目例会定在周四上午十点 |
| 4 | 普通事实 | 测试库密码轮换周期 | 演示记忆：测试环境的数据库密码每月轮换 |
| 5 | 普通事实 | 演示项目代码托管位置 | 演示记忆：演示项目的代码仓库托管在 GitHub |
| 6 | 近似变体（与 #1 构成近似对，写入时观察相似提示） | 金营平台生产部署架构 | 演示记忆：金营平台的生产部署采用双可用区架构（终版） |

`entity: demo-deployment, scope: demo-deployment-scope`）——写时冲突检测的
配对前提，缺了不触发。

## 3. 能力演示（标准话术 + 实操）

每步向用户展示「输入了什么 → mema 返回了什么」。

**① 记忆与查询**
> 「刚才写进去的内容，现在换个说法去查它——不用记得原话，意思差不多就能找到。」
> 「查出来的每条前面都有个编号，你想看哪条的完整内容，报个编号我直接取给你。」

实操：`memory(action="find", data={"query": "生产部署架构是什么样的", "limit": 5})`
展示命中列表（含 memory ID）→ 挑一条 `memory(action="read", data={"memory_id": <id>})`
展示全文。给用户看的形态：**编号 + 一句话主题**（不贴整段原始返回）。
演示全程不指定 workspace（写入与查询都走默认，行为一致）；准确率
汇报前核对命中条目——带 `mema-demo` 标签的才算演示数据命中，混入的真记忆
如实分开说，不得算进演示命中率。

> 「顺带说一个内部机制，你不用做任何事：迷码存东西是按『抽屉』分的——
> 一个项目一个抽屉。查询可以只翻某个抽屉；查重、查矛盾也是同一个抽屉里
> 两两对照的——所以两条相关的事要是进了不同抽屉，就互相照不上面了。好在
> 抽屉完全不用你操心，也别手动去分：默认所有东西放一起，迷码会自己归类
> 整理，拿不准的才会来问你。刚才的演示内容就是按默认方式存的。」

**② 相似提醒（写入时）**
> 「迷码写入时会顺手查一道：这条是不是跟已有的内容高度重复——刚才那条带
> 『（终版）』的，就跟第一条几乎一样，当场被它抓到提醒了。这样库里不会
> 攒下一堆重复的说法。」

实操：展示写近似条时返回里的 `similar_active_memory` 提示（matches 列表）。
给用户看的形态：**两句原文并排 + 一句白话**（「这两条几乎一样，迷码提醒了」），
相似度数字可以说成「像到什么程度」，不贴原始 JSON、不念字段名。
若未触发，**如实向用户说明没触发**，不得圆场、不得跳过不提。

**③ 冲突提醒（写入时/事后）**
> 「写入前后打架的说法时迷码也会提醒——刚才两条，一个说数据库用的是
> MySQL、一个说用的是 PostgreSQL，写入的当下（或稍等一两秒）就被它抓到
> 了。这种矛盾不处理的话，以后问起来会拿到两个打架的答案。」

实操：优先看写冲突条的返回——模型预热（服务默认 preload）的常态下，
notice 在同步窗（默认 3 秒）内直接出现在写响应里（真机实测 0.7s）。
给用户看的形态：**把对立的两句原文并排列出**（「一个说 MySQL、一个说
PostgreSQL」），再说一句白话（「迷码发现这两条打架了，留哪个由你以后定」），
不贴原始返回。没出时按序兜底：① 继续做 §3① 的查询演示，notice 会随下一次
任意工具响应自动附带投递；② 等 3~5 秒查 `memory_repair(task="notice", data={"action": "list"})`。
模型不可用 → 按话术标注「这项没测成」，不伪报通过或失败。

## 4. 准确率汇报（标准话术，诚实口径）

演示后立即汇报，只报演示数据的命中情况：

> 「刚才的演示成绩，照实说：8 条测试内容里，我用『生产部署架构』这句话去查，
> 找到了 X 条、最好的那条排第 N 位；两次『写重了』的测试——一条是加了
> 『（终版）』的重复说法、一条是那对矛盾里文本很像的那条——迷码提醒了
> X 次，应该 2 次；一次『说法打架』的测试，迷码提醒了 X 次，应该 1 次。
> 这只是在演示内容上的成绩，不代表平时在你自己记忆里的准确率。」

## 5. 能力与好处（标准话术，全文照念）

> 「迷码就是 AI 的长期记忆管家。刚才那套演示，连起来是这么回事：
>
> ```
>  你（平时只管正常说话）
>    │  「记住：例会改到周四十点」
>    ▼
>  AI 助手 ──写进──▶ 迷码（你电脑上的一个账本文件）
>    ▲                    │
>    └──「上次例会定几点来着？」──┘
>  换个会话、换个 AI 助手，连的还是同一个账本
> ```
>
> 六个本事：
> 一、记得住——你确认过的事实原样保存，跨会话不丢，还能查到是谁说的、
> 什么时候说的；
> 二、查得准——意思相近就能找到，不用背原话，找到后报编号看全文；
> 三、防重复——写入时发现跟已有内容高度重复，当场提醒；
> 四、防矛盾——发现新旧说法打架，当场或事后提醒，留哪个由你来定；
> 五、能体检——随时能检查整个记忆库健不健康、有没有待处理的矛盾；
> 六、看得见——在浏览器里就能翻看记忆库的全貌，一条命令的事。
> 好处一句话：你说过的话变成靠得住的底账，AI 不用每次重新问，也不会拿着
> 过时的、打架的旧说法来做事。」

## 6. 兜底扫描授权（标准话术）

> 「刚才演示的检查是『写入的当下查一遍』，难免有漏网的。迷码还能定期把
> 整个记忆库从头到尾翻一遍来兜底。建议开两个自动任务：
> ①深夜大扫除——自动跑，只找问题，不打扰你；
> ②每周提醒——定期看看扫出来的结果，真有需要你拍板的才来问你。
> 什么时候跑、多久跑一次，你说了算（没偏好的话用建议值：大扫除每周一次
> 挑深夜、提醒挑工作日早上）。要开吗？开一个还是两个？」

**硬要求**：必须按话术询问用户，**不得由 agent 代用户决定开不开、开几个、
什么时间**——实测放开让 agent 自行判断时，用户几乎不会被问到，授权门形同虚设。

实操：用户同意后，通过宿主平台的定时任务机制创建（等价于 mema
SCHEDULED_TASKS_SPEC 的 conflict_scan 与 governance_reminder 两个任务；mema 侧
无内置守护进程）。时间未指定时用建议默认：conflict_scan 每周凌晨 3:00、
governance_reminder 每周三 8:30。用户不同意则跳过，告知可随时补开。

## 7. 清理（必做，标准话术）

> 「演示结束，我把那 8 条测试内容清掉。清的方式是标记作废——底账里留个
> 记录、以后查得到，但它们不会再出现在你的任何查询里，等于删掉了。」

实操：`memory(action="find", data={"query": "", "tags_filter": ["mema-demo"]})`
列出全部 demo 记忆 → 逐条 `memory_govern(action="retire", data={...})`，
retire reason 注明 `mema_feature_demo cleanup run_id=<run_id>`；
retire 调用带 `authorized=true`——同意门的一次性授权覆盖写入与清理，
否则逐条 retire 都会卡授权门。

**清理失败必须向用户列出残留记忆 ID**，并建议人工 retire。不得静默留下残骸。

清理完成后，demo 产生的冲突 notice 自动失效（转 stale，仅审计可查），
open 列表零残留（真机实测），无需向用户说明残留。

**清理闭环后必须写全局标记（§0 一次原则的收口）**：

```
memory(action="remember", data={"content": "首次功能演示已完成（<日期>，run_id=<run_id>，agent=<宿主名>）。",
  "subject": "mema 首次演示状态：已完成", "tags": ["mema-first-run-demo-status"]})
```

标记与演示数据不同标签（`mema-first-run-demo-status` ≠ `mema-demo`），**不参与
§7 清理、永不被本演示 retire**。清理失败残留时也要写标记（注明残留 ID）——
提示过一次就绝不再提示，与清理成败无关。

## 8. 演示结束（标准话术）

> 「演示到这里。平时用不需要任何特殊操作——你聊天里让我『记住』的事，
> 会自动进这套体系。
> 最后一个建议：让我把『凡是跟工作相关、值得跨会话记住的内容，都记进
> 迷码』这条约定写进我自己的本地小本子。这样以后每次新开会话我都自觉记，
> 不用你提醒。要做吗？」

实操：用户点头后写入宿主 Agent 自己的本地持久指令/记忆文件（各宿主文件名
不同，agent 自知）；这是 mema 之外的写入，话术末尾的「要做吗」就是征求同意，
用户拒绝则跳过。
